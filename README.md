# 🥜 PeanutDB

PHP로 구현한 경량 파일 기반 Key-Value 데이터베이스 엔진입니다. 
데이터를 파일에 저장하고, 메모리 기반 B+Tree 인덱스를 이용해 레코드의 파일 위치(Offset)를 찾아 조회합니다.

## 1. 프로젝트 목적

데이터베이스가 데이터를 디스크에 저장하고 인덱스를 통해 조회하는 과정을 직접 구현하며, **인덱스 사용 여부에 따른 저장 및 검색 성능의 차이**를 비교합니다.

## 2. 현재 구현 구조

| 구성 요소 | 역할 |
| --- | --- |
| `FileStorage` | 인덱스 없이 파일에 데이터를 저장하고 스캔하여 조회 |
| `IndexedFileStorage` | 파일에 레코드를 기록하고 Offset을 기반으로 읽기 |
| `BPTree` | 메모리에 Key → Offset 인덱스 구성 |
| `PeanutDB` | 파일 저장소와 B+Tree 인덱스를 연결 |

현재 B+Tree의 노드 자체는 RAM에 존재합니다. 데이터 파일은 디스크에 저장되며, DB를 다시 열 때 파일을 스캔하여 인덱스를 재구성합니다.

## 3. 성능 비교

### 측정 방법

- 실행 명령: `php tests/IndexPerformanceTest.php`
- 데이터 수: 1,000 / 5,000 / 10,000건
- 각 데이터 수마다 100회 조회
- 측정 항목: 저장, 조회, 인덱스 재구성(재오픈)
- 측정 단위: ms

| 데이터 수 | 전체 스캔 저장 | B+Tree 저장 | 전체 스캔 조회 (100회) | B+Tree 조회 (100회) | 인덱스 재오픈 |
| --- | --- | --- | --- | --- | --- |
| 1,000건 | 130.04 ms | 7,643.20 ms | 73.74 ms | 2.21 ms | 3.28 ms |
| 5,000건 | 576.35 ms | 78,607.31 ms | 327.62 ms | 2.32 ms | 16.23 ms |
| 10,000건 | 1,206.05 ms | 173,056.00 ms | 685.82 ms | 3.85 ms | 36.27 ms |

### 결과 분석

**검색 성능**

B+Tree를 사용한 조회는 데이터가 증가해도 측정 시간이 상대적으로 적게 늘었습니다. 
10,000건에서 100회 조회 기준, 전체 스캔(685.82 ms) 대비 B+Tree(3.85 ms)가 **약 178.1배 빠르게** 측정되었습니다.

**저장 성능**

반대로 B+Tree 방식의 저장 시간이 크게 증가했습니다. 
10,000건에서 전체 스캔 방식의 저장(1,206.05 ms) 대비 B+Tree 방식의 저장(173,056.00 ms)이 **약 143.5배 오래 걸렸습니다.** 


**인덱스 재구성 시간**

현재 인덱스는 RAM에만 존재하므로 DB를 다시 열면 데이터 파일을 스캔해 B+Tree를 다시 구성합니다. 데이터가 증가할수록 재오픈 시간이 3.28 → 16.23 → 36.27 ms로 증가했습니다. 벤치마크 코드가 재오픈 후 조회도 수행한다면 해당 조회 시간도 수치에 포함됩니다.
